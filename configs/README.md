# Configuration

`qwen_prefix_shared.yaml` selects the shared-model `qwen_prefix` runtime in the main C++ CLI/service. It requires one process, one inference slot/model, `workers.scheduler=round_robin`, 1–8 `workers.max_sessions_per_process`, and real-time mono 16 kHz PCM. `model.prefix_preview_ms` sets the first provisional prefix length (default 4000); EOF always performs a full-audio final decode. `model.threads`, `model.timeout_ms`, and worker idle/total budgets apply; deadlines are soft because an active native decode cannot be interrupted. Native live `decode_step_ms` and token-cap settings apply to `qwen_native`, not prefix redecoding. CPU affinity is supported only by the process-isolated runtime. Main load/sweep preflight counts shared model/scratch once and bounds PCM at 60 seconds per call. See [results and main-service reproduction](../docs/TIME_MULTIPLEXING_RESULTS.md).

M4 adds `metrics.resource_sampling` (default `true`) and `metrics.sample_interval_ms` (default `200`, range `50..5000`). Real sampling is skipped for simulated clocks with an explicit reason. Native process environment applies custom/BLAS thread budgets before library initialization. See [M4 guide](../docs/m4-code.md).

M5 adds `workers.processes` (1–4), separate slot/session/model-instance controls (currently each must equal 1), `workers.scheduler` (`least_active` or `round_robin`), idle/total deadlines, and optional native `cpu.affinity_enabled` plus `cpu.cores`. Resolved JSON includes executor kind and threads per process. The CLI still runs one call; process count is capacity for future concurrent ingress, not a request to start that many models. See [M5 guide](../docs/m5-code.md).

`mock_baseline.yaml` is the executable mock configuration; `qwen_native_single.yaml` is the M3 native single-call example. `qwen_native_threads2.yaml` changes only `model.threads` from four to two for the M9 one-factor screen. `qwen_native_ui_overhead.yaml` fixes a short real-WAV native workload for the M8 paired dashboard screen. `src/config.cpp` resolves defaults → YAML → CLI overrides, validates the supported subset, and exposes resolved JSON. Relative output, WAV, and model paths are based on the YAML directory. M2 adds WAV source and channel-mix settings; M3 adds pinned `qwen_native` runtime, threads, decode step, token cap, timeout, and EOF refinement. See `docs/m2-code.md`, `docs/m3-code.md`, and `docs/m9-code.md`. Machine, engine, and suite folders remain reserved; M0 probes retain their separate arguments.
